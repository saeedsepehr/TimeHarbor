# Privacy

TimeHarbor has no analytics, telemetry or advertising. Local operation needs no account. The shipped 0.4 development build has Google connection disabled until the owner's OAuth service is configured and tested. Browser networking to the websites you visit is independent of this addon.

It stores settings, domain-level usage durations, pause counters and break/quota state in `browser.storage.local`. It does not intentionally store browsing-page contents, titles, keystrokes, passwords or full URL histories. The currently blocked page URL is carried locally in the extension lock-page URL so the user can return to it. Content scripts observe interaction event timing and HTML media playback state, not the text being typed.

Break activity records include the configured domain, profile ID, break start/end timestamps, configured checklist labels, selected labels and whether the break was skipped. They are self-reported, stay local and follow the configured retention period, with a maximum of 10,000 records. The report view displays the latest 100 matching break records; the current CSV export covers website usage. Clear reports removes both usage and break records without resetting the website quota.

Reports can cover configured websites only (default) or all visited ordinary HTTP(S) domains, as selected in Settings. Retention defaults to 90 local calendar days and can be changed. Shortening retention removes older records at the next persisted checkpoint or configuration save. CSV export is explicitly initiated by the user and stays wherever they save it.

The four-digit settings PIN is stored as a salted PBKDF2-SHA256 verifier, using 310,000 iterations. Plaintext PINs are not persisted or logged. Authorization sessions are kept in extension session storage and expire after ten minutes. Failed-attempt backoff persists locally. A local PIN does not protect against someone controlling the device or the extension's files/storage.

Manual settings exports contain configured domains, break profiles and general preferences. They exclude PIN verifiers, authorization sessions, usage reports and break records. Imports replace settings after validation and confirmation; the destination PIN is retained. The downloaded file is not encrypted: store/share it according to the sensitivity of your configured website list. In Chromium, recent tab observations are checkpointed in browser session storage for service-worker recovery and do not form a persistent URL history.

If Google sync is configured and you explicitly connect/consent, recorded domains, usage durations and consumed activity intervals are sent directly to your Google Drive app-data folder, along with settings and revision metadata. Reporting scope still applies: selecting all visited domains includes them in the optional sync. PINs, local authorization sessions and break check-in records are excluded. This is not an end-to-end encrypted backup claim. Google controls the account/storage service.

The OAuth broker handles authorization codes and Google tokens during exchange/refresh, not browsing reports. Its operator must be trusted with that authorization exchange. The implementation does not persist tokens or log request/response bodies on the broker; hosting access/query logging must also be disabled during deployment. Client Secret and state-signing keys belong only in the server environment. Refresh credentials are retained in privileged local extension storage; access credentials and pending PKCE state use session storage. They are never returned to content scripts, settings exports or public messages. Local browser-profile control remains outside the protection of the four-digit PIN.

While connected, local consumed-interval records are retained for reporting and shared quota calculation, with at least eight days needed for supported multi-day quota windows even if report retention is shorter. Cloud pulls are bounded to at most 90 days of history (plus quota needs), two MiB per document and four MiB of cached remote documents. Old Drive backup files are not automatically deleted; manage/remove the app's stored data through Google Drive app management. Disconnect removes this browser's credentials/cache and stops future cloud requests, without deleting Drive backups or disconnecting other installations. In-flight requests may finish. Cloud live acceptance has not yet been performed.

The addon requests HTTP(S) host access to observe activity and block top-level navigation; `tabs` for tab/window identity and redirects; `storage` for local state; `alarms` for recovery/checkpoints; `webRequest`/`webRequestBlocking` for Firefox navigation enforcement, or `declarativeNetRequestWithHostAccess` in Chromium. Chromium exposes only the packaged lock-page document for redirects. Internal browser pages and restricted origins have different access rules.

The About page contains external contact/project links. These are opened only when you choose a link, and their services' own privacy policies then apply. It does not embed remote social widgets, fonts or tracking images.

The alpha does not download online blocklists yet. If that feature is added, its provider, requests, license and update behavior will be documented before release.

Development-only tests use dummy domains/PINs and an isolated Firefox profile; a test-only script sends synthetic test outcomes to a loopback HTTP server. That script is never included in the production `dist/` or packaged ZIP.
